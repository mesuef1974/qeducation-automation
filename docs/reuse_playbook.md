# دليل إعادة الاستخدام: صفوف أو فصول أو مواد جديدة

هذا الدليل يجمع كل خطوات الأتمتة بالترتيب، من التثبيت حتى المهمة الثانية. وفي آخره ما يجب تعميمه في الكود قبل التوسع.
- تفاصيل المنصة (المسارات والحقول وسلوكها): [platform_map.md](platform_map.md).
- سجل كل مهمة وسياستها ونتيجتها: [automation_tasks.md](automation_tasks.md).

## 0. التثبيت (مرة واحدة لكل جهاز)
```
python -m pip install -r backend/requirements.txt
python -m playwright install msedge        # أو يكفي Edge المثبّت على ويندوز
python backend/manage.py migrate
```
الخادم المحلي: `python backend/manage.py runserver 127.0.0.1:8765`. الدخول تلقائي كمدير، والطلبات مقبولة من الجهاز نفسه فقط.

## 1. قاعدة الخطة الفصلية
المصدر: ملف PDF الرسمي (نموذج ES-ESM-P3-F1).
1. أدخل محتوى الخطة في `PLANS` داخل `db/build_db.py`:
   - الوحدات.
   - الجدول، وكل صف فيه (أسبوع، وحدة، نوع، رمز الدرس، العنوان، الحصص).
   - مجاميع الأسابيع في `EXPECTED_WEEK_TOTALS`.
2. حدّث `TERM_START` (أحد الأسبوع الأول) وأحداث `COMMON_EVENTS`، وغيّر اسمَي الملفين `DB_PATH` و`XLSX_PATH`.
3. شغّل `python -I db/build_db.py`. الخطوة `verify()` توقف البناء إن خالف مجموعُ أسبوع الخطةَ.
4. وجّه Django إلى القاعدة الجديدة إما عبر `PLANS_SOURCE_DB` أو متغير البيئة بالاسم نفسه، ثم شغّل `python backend/manage.py import_plans`.

تنبيه: `import_plans` يستبدل كل الخطط الحالية، فانظر القسم 5.

## 2. ربط صفوف المنصة
1. افتح الصف على المنصة. رقمه هو الرقم الذي في الرابط `/teacher_lessons/list/{LMS_ID}`.
2. أضفه إلى `NEO_CLASSES` في `backend/config/settings.py` بالشكل `LMS_ID: (المستوى, "اسم الصف كما في المنصة")`.
3. تحقّق من أن الخيارات الثلاثة الآتية مفعّلة في إعدادات الصف على المنصة:
   - تعيين الدرس الحالي تلقائيًا حسب التاريخ.
   - إسناد التقييمات تلقائيًا.
   - إظهار التقييمات تلقائيًا عند وقت البدء.

   المهمة 2 تعتمد عليها.

## 3. الدخول
`python backend/manage.py neo_login` يفتح المتصفح، فيسجّل المعلم الدخول بنفسه. لا تُخزَّن كلمة مرور، وتُحفظ كوكيز الجلسة في `backend/.neo_profile/`. أعد الأمر متى ظهرت رسالة «انتهت الجلسة».

## 4. المهام (القراءة أولًا، والكتابة بعد اعتماد المعلم)

| المهمة | اقتراح (قراءة فقط) | تطبيق (كتابة على المنصة) |
|---|---|---|
| 1. تواريخ الدروس | `neo_sync` | `neo_sync --apply RUN --approve future\|all` |
| 2. إسناد التقييمات | `neo_assign` | `neo_assign --apply RUN --approve all` (جرّب أولًا `--limit 1`) |

الترتيب ملزم: المهمة 2 تحسب مواعيد كل تقييم من تاريخ درسه، فشغّل المهمة 1 قبلها. كل التطبيقات idempotent، وإعادتها لا تكرر شيئًا. ويمكن مراجعة الاقتراحات واعتمادها من لوحة الإدارة `/admin/neo/`.

### قائمة تحقق لكل صف أو فصل جديد
- [ ] الصف يطابق الخطة: اقرأ ناتج `neo_sync`، ففيه الدروس غير المطابقة وبنود الخطة المفقودة من المنصة.
- [ ] جدول الحصص في المنصة صحيح، لأن الاقتراحات مبنية عليه.
- [ ] السياسة `NEO_ASSIGN_POLICY` ما زالت هي المطلوبة.
- [ ] `python -m pytest backend` ينجح بعد أي تعديل.

## 5. فجوات قبل التوسع (لم تُعالَج بعد)
كل واحدة من هذه تمنع تشغيل أكثر من خطة للمستوى نفسه:

| الفجوة | الموضع | الأثر |
|---|---|---|
| الصف يُربط بالخطة عبر المستوى وحده | `PlatformClass.plan` في `neo/models.py`، و`PlanRepository.get_by_grade` | مادتان أو فصلان للمستوى نفسه يتعارضان |
| القيد الفريد (العام، الفصل، المستوى) بلا المادة | `curriculum/models.py` و`db/build_db.py` | لا يقبل خطتين لمادتين في المستوى نفسه |
| `import_plans` يستبدل كل الخطط | `curriculum/services/import_service.py` | استيراد فصل جديد يمحو القديم |
| الصفوف مثبّتة في الإعدادات | `NEO_CLASSES` | الإضافة تحتاج تعديل كود؛ الأفضل إدارتها من لوحة الإدارة |
| بيانات الخطة مكتوبة يدويًا في الكود | `PLANS` في `db/build_db.py` | كل خطة جديدة تحتاج إدخالًا يدويًا من PDF |
| عرض الأحداث مثبّت على المستوى 10 | `curriculum/api/views.py` | يعرض أحداث العاشر فقط |
| المطابقة مضبوطة على عناوين الرياضيات العربية | `neo/services/matching.py` | مادة أخرى قد تحتاج ضبطًا ثم اختبارًا |

الحل المقترح:
- يُربط الصف بخطة محددة بمفتاح (مادة، عام، فصل، مستوى).
- يُستورد بالإضافة بدل الاستبدال.
- تُدار الصفوف من لوحة الإدارة.
- يُستورد ملف خطة بصيغة موحّدة (Excel أو JSON) بدل تعديل `build_db.py`.
